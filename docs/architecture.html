Architecture#

The scatterem package is a stack of layers. Each layer is one or more subpackages. A module imports only from its own subpackage and from lower layers. It never imports from a higher layer. Thus the physics does not depend on the solvers, and the solvers do not depend on plotting or on the paper datasets.

The core has seven layers, from the forward physics (layer 0) to the reconstruction methods (layer 6). Three small base layers sit below the core: settings, rotations and crystals. The paper datasets and the root scatterem namespace sit above it.

The bold rows are the seven core layers. Two subpackages in the same layer do not import each other. For example, nn does not import vis.

The import rule#

A module in layer n imports from layers below n only. There is one exception: scatterem.reconstruction reads scatterem.__version__ from the root namespace, to write it into the run record.

The rule has these results for users:

  1. Import from the subpackage that holds a name, for example from scatterem.physics.optics import lens_wavefront. The root namespace re-exports only the FF-STEM entry points, Dataset4DStem, the paper datasets and configure.

  2. A lower layer does not call the higher layers. For example, a potential built with scatterem.physics runs no reconstruction code. (An import of any subpackage still runs the root scatterem/__init__.py, which imports scatterem.reconstruction.)

  3. Plotting is optional. Only vis imports matplotlib at import time. A lower layer loads matplotlib only when one of its plotting functions runs.
